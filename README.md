## 프로젝트 개요

자연어 처리(NLP, 사람이 쓰는 말과 글을 컴퓨터가 다루게 하는 기술)는 검색 엔진, 추천 시스템, 스팸 필터 같은 서비스의 핵심이다. 이 미션에서는 뉴스 기사나 리뷰 데이터로 **문서 검색 및 분류 시스템**을 만든다. 글을 숫자 벡터(숫자 묶음)로 바꾸는 과정, 즉 토큰화(글을 단어 같은 조각으로 자르기), TF-IDF 벡터화(단어가 한 문서에 얼마나 자주, 전체 문서에서 얼마나 드물게 나오는지로 점수 매기기), 유사도 계산을 직접 구현한다. 이를 통해 "단어의 출현 빈도만으로 문서의 의미를 파악할 수 있는가?"라는 질문에 답하고, BoW(Bag of Words, 단어 순서를 무시하고 단어 개수만 세는 방식)의 가능성과 한계를 체감한다.

**핵심 과제** (명세의 "기능 요구 사항")

1. 500개 이상 문서로 데이터를 준비하고 전처리(정제, 토큰화, 불용어 제거)한다.
2. NumPy로 TF-IDF를 직접 구현하고 Scikit-learn 결과와 오차 1e-6 이내인지 검증한다.
3. 코사인 유사도로 쿼리와 비슷한 문서 상위 5개를 찾는 검색 시스템을 만든다.
4. TF-IDF 벡터로 분류 모델을 학습하고 성능과 오분류 원인을 분석한다.

## 개발 환경과 제약 사항

**개발 환경**

- Python 3.10 이상
- 허용 라이브러리: Pandas, NumPy, Matplotlib/Seaborn, KoNLPy(한국어), NLTK(영어), Scikit-learn(분류/검증용)
- requirements.txt 제출 필수

**금지 사항**

- TF-IDF 핵심 로직에 NumPy 외의 라이브러리를 쓰지 않는다. Scikit-learn은 **검증 용도로만** 쓴다.
- 코사인 유사도를 라이브러리 함수로 계산하지 않는다. NumPy 벡터 연산으로 직접 구현한다.
- 개인정보(식별 가능한 이름, 연락처, 건강정보 등)가 포함된 데이터를 쓰지 않는다. 공개 데이터셋을 우선 사용한다.

**데이터셋 조건**

- 최소 2개 이상 카테고리를 포함하는 분류 문제를 다룬다.
- 데이터 준비 체크리스트 (명세 참고 사항)
  - [ ] 500개 이상 문서 확보
  - [ ] 2개 이상 카테고리 포함
  - [ ] Train/Test 분리 가능

### 추천 A: KLUE YNAT (한국어 뉴스 제목, 7개 카테고리)

명세의 "AI Hub 한국어 뉴스 데이터"와 같은 성격(카테고리별 뉴스)이면서, 회원가입 없이 받을 수 있고 라이선스가 공개되어 있다.

| 항목 | 내용 |
|---|---|
| 데이터셋 | [KLUE YNAT](https://huggingface.co/datasets/klue/klue) (KLUE 벤치마크의 주제 분류 과제) |
| 라이선스 | CC BY-SA 4.0 (확인, [KLUE 공식 GitHub](https://github.com/KLUE-benchmark/KLUE)) |
| 규모 | train 45,678건, validation 9,107건 (Hugging Face 데이터 카드 기준) |
| 필드 | `guid`, `title`(뉴스 제목), `label`, `url`, `date` |
| 카테고리 | IT과학, 경제, 사회, 생활문화, 세계, 스포츠, 정치 (7개) |

| 요구사항 | 해결 방법 |
|---|---|
| 500개 이상 문서 | train만 써도 4만 건이 넘는다. 실험 속도를 위해 카테고리마다 같은 수로 일부(예: 수천 건)만 뽑아 써도 된다 |
| 2개 이상 카테고리 | 7개 전부 쓰거나, 혼동 행렬을 읽기 쉽게 3~4개만 골라 쓴다 |
| Train/Test 8:2 | 명세는 직접 8:2로 나누라고 하므로, 받은 데이터를 합쳐서(또는 train만으로) `random_state`를 고정해 다시 나눈다 |
| 검색 결과 (점수, 문서 ID, 스니펫) | `guid`를 문서 ID로, `title`을 스니펫으로 쓴다 |
| 오분류 분석 (BoW 한계) | "경제"와 "IT과학", "사회"와 "생활문화"처럼 겹치는 주제가 있어 오분류 사례를 찾기 쉽다 |

**약점**: 본문이 아니라 **뉴스 제목**만 있다. 문서 하나가 짧아서 단어가 몇 개밖에 없고, 검색 쿼리와 겹치는 단어가 없으면 유사도가 0이 되는 일이 잦다. 이 점은 오히려 "BoW 방식의 한계" 사례로 리포트에 쓸 수 있다.

### 추천 B: NSMC (네이버 영화 리뷰, 긍정/부정)

명세가 한국어 1순위로 추천한 데이터다. 라이선스가 가장 자유롭고, 다음 미션(A4-2)의 감성 분석에 그대로 다시 쓸 수 있다.

| 항목 | 내용 |
|---|---|
| 데이터셋 | [NSMC](https://github.com/e9t/nsmc) |
| 라이선스 | CC0 1.0 (확인, 저장소 README의 라이선스 표시) |
| 규모 | 전체 20만 건 (`ratings_train.txt` 15만, `ratings_test.txt` 5만), 긍정·부정 각 10만 건 |
| 필드 | `id`, `document`(리뷰 본문), `label`(0 = 부정, 1 = 긍정). 탭으로 구분된 텍스트 파일 |

| 요구사항 | 해결 방법 |
|---|---|
| 500개 이상, 2개 카테고리 | 충분하다. 긍정/부정 2개가 카테고리가 된다 |
| 결측치 제거 | 리뷰 본문이 빈 행이 있을 수 있으므로 `document`의 결측치를 확인하고 지운다 |
| 검색 결과 | `id`를 문서 ID로, `document`를 스니펫으로 쓴다 |

**약점**: 리뷰가 140자 미만으로 짧고, 카테고리가 "주제"가 아니라 "기분"이다. "딥러닝 이미지 분류" 같은 주제 검색 예시와는 잘 맞지 않는다. 검색은 "배우 연기", "결말 반전"처럼 영화 리뷰에 맞는 쿼리로 시연한다.

**영어를 고른다면**: [Twenty Newsgroups](https://archive.ics.uci.edu/dataset/113/twenty+newsgroups)(CC BY 4.0, 확인)가 1순위다. Scikit-learn의 `fetch_20newsgroups`로 바로 받을 수 있고, 문서가 길어서 검색 시연에 좋다. 단, 게시물 머리말(header)에 이메일 주소와 이름이 들어 있으므로 `remove=('headers', 'footers', 'quotes')`로 지우고 쓴다.

### 데이터를 다룰 때 주의할 점

- **데이터 파일은 레포에 올리지 않는다.** `data/` 폴더에 두고 `.gitignore`로 제외한다. README에는 다운로드 위치, 출처, 라이선스만 적는다. 특히 CC BY-SA(YNAT)는 데이터를 다시 배포하면 같은 라이선스를 붙여야 하므로, 올리지 않는 쪽이 간단하다.
- **출처 표기**: CC BY 계열은 출처를 밝혀야 한다. 예: `KLUE YNAT (Park et al., 2021), CC BY-SA 4.0, https://github.com/KLUE-benchmark/KLUE`. CC0(NSMC)는 의무는 없지만 출처를 적어 두는 것이 좋다.
- **명세의 NSMC 로드 예시 수정**: 명세 예시는 `pd.read_csv('ratings_train.txt', sep=' ')`인데, NSMC 파일은 **탭**으로 구분되어 있다(저장소 README). `sep='\t'`로 읽어야 한다.
- **개인정보 확인**: 뉴스 제목과 리뷰에도 사람 이름이 나올 수 있다. 공인의 이름이 기사에 나오는 것은 공개 데이터의 일반적인 내용이지만, 리포트에 오분류 사례를 옮길 때 일반인의 연락처 같은 정보가 섞여 있지 않은지 본다.
- **실험 규모**: 수만 건 전체로 TF-IDF 행렬을 NumPy로 만들면 메모리를 많이 쓴다. 처음에는 카테고리별로 같은 수만큼 뽑은 수천 건으로 시작하고, 뽑을 때도 `random_state`를 고정한다.

## 할 일

명세의 기능 요구 사항이다. 끝낸 항목은 `[x]`로 바꾼다.

### 1. 데이터 준비 및 전처리

글을 컴퓨터가 셀 수 있는 단어 조각으로 깨끗하게 자르는 단계다. 불용어(stopword)는 "은, 는, the, a"처럼 너무 흔해서 의미 구분에 도움이 안 되는 단어다.

- [ ] 최소 500개 이상의 문서가 포함된 텍스트 데이터셋을 사용한다.
- [ ] 텍스트 정제(특수문자 제거, 소문자 변환 등)를 수행한다.
- [ ] 토큰화를 구현한다. (한국어: 형태소 분석기 권장, 영어: NLTK 또는 공백 기반)
- [ ] 한국어 형태소 분석기 설치가 어려워 공백 토큰화를 대안으로 쓴 경우, "성능이 왜 달라지는지"를 리포트에 분석한다.
- [ ] 불용어 목록을 정의하고 제거한다.
- [ ] 전처리 기준(특수문자 제거 범위, 불용어/동의어 처리 기준)을 직접 설계하고 근거를 리포트에 서술한다.

### 2. TF-IDF 직접 구현

TF(Term Frequency)는 한 문서 안에서 단어가 몇 번 나왔는지, IDF(Inverse Document Frequency)는 그 단어가 전체 문서 중 몇 개에 나오는지의 역수에 로그를 씌운 값이다. 둘을 곱하면 "이 문서에서는 자주 나오지만 다른 문서에는 드문 단어"가 높은 점수를 받는다.

- [ ] NumPy를 사용하여 TF-IDF 행렬을 계산하는 함수를 작성한다.
- [ ] TF 계산: 문서 내 단어 빈도를 행렬로 표현한다.
- [ ] IDF 계산: 전체 문서 대비 단어 출현 문서 수의 역수(로그 적용)를 계산한다.
- [ ] 구현 결과를 Scikit-learn `TfidfVectorizer`와 비교하여 오차가 1e-6 이내인지 검증한다.
- [ ] 검증 재현성 확보: sklearn의 `sublinear_tf`, `smooth_idf`, `norm` 등의 파라미터를 직접 구현체와 동일하게 설정하고, 어떤 설정으로 검증했는지 README에 명시한다.

### 3. 문서 검색 시스템

검색어도 문서와 같은 방식으로 벡터로 바꾼 뒤, 두 벡터가 가리키는 방향이 얼마나 비슷한지(코사인 유사도, 1에 가까울수록 비슷함)로 문서를 고른다.

- [ ] 쿼리를 TF-IDF 벡터로 변환한다.
- [ ] 코사인 유사도를 NumPy 벡터 연산으로 직접 계산한다.
- [ ] 유사도 상위 5개 문서를 반환한다. (점수, 문서 ID, 텍스트 스니펫 포함)

### 4. 문서 분류 실험

TF-IDF 벡터를 입력으로 넣어 문서의 카테고리를 맞히는 모델을 학습한다. 혼동 행렬(confusion matrix)은 실제 정답과 예측을 표로 세어, 어떤 카테고리를 어떤 카테고리로 헷갈렸는지 보여 준다.

- [ ] TF-IDF 벡터를 특성으로 사용하여 분류 모델을 학습한다.
- [ ] 기본선: Logistic Regression 또는 Linear SVM 중 택1, Train/Test 8:2, `random_state` 고정
- [ ] 정확도, F1-Score를 측정한다.
- [ ] 혼동 행렬을 시각화한다.
- [ ] 오분류된 문서 5개 이상의 원인을 분석한다. (BoW 한계와 연결하여 서술)

## 보너스 과제

### 보너스 1. 다양한 TF 변형 구현

### 보너스 2. BM25 구현

BM25는 TF-IDF를 개선한 검색 점수 공식으로, 같은 단어가 너무 많이 나와도 점수가 끝없이 커지지 않게 하고 문서 길이도 고려한다.

- [ ] BM25의 수식을 이해하고 NumPy로 직접 구현한다.
- [ ] 동일한 쿼리에서 TF-IDF와 BM25 검색 결과를 비교 분석한다.

### 보너스 3. 역색인(Inverted Index) 구현

역색인은 책 뒤의 "찾아보기"처럼 단어마다 그 단어가 들어 있는 문서 목록을 미리 적어 둔 구조다.

- [ ] 단어 → 문서 ID 리스트 형태의 역색인 구조를 구현한다.
- [ ] 역색인 기반 검색과 전체 스캔 검색의 시간 복잡도를 비교한다.

## 결과 예시 (명세 참고)

명세는 "정답이 아니라 참고 예시이며, 실제 문구와 구조는 달라도 된다"고 밝힌다. 예시는 다음을 보여 준다.

- **TF-IDF 검증**: 행렬 shape, 사용한 sklearn 설정, 최대/평균 오차, PASS 여부를 출력한다.
- **코사인 유사도 계산 과정**: 쿼리 벡터와 문서 벡터, 공식 (Query · 문서) / (‖Query‖ × ‖문서‖)에 숫자를 넣은 계산을 보여 준다.
- **검색 결과**: 쿼리 하나에 대한 Top 5 결과를 점수와 스니펫으로 보여 준다.
- **분류 성능**: 모델, Train/Test 개수, 정확도, F1-Score(macro)를 출력한다.
- **오분류 분석**: 예측/실제 카테고리, 문서, 원인, BoW 한계를 케이스별로 적는다.
- **BoW 한계 분석**: 어순 무시("고양이가 쥐를 잡았다" vs "쥐가 고양이를 잡았다"), 동음이의어("배") 사례를 든다.

TF-IDF 검증 출력 형식 예시:

```
=== TF-IDF 구현 검증 결과 ===
TF-IDF 행렬 shape: (500, 3247)
[검증] 직접 구현 vs Scikit-learn
 - sklearn 설정: smooth_idf=True, sublinear_tf=False, norm='l2'
 - 최대 오차: 8.32e-10
 - 평균 오차: 1.05e-12
 - 결과: PASS (허용 오차 1e-6 이내)
```

나머지 출력 예시는 명세 PDF의 결과 예시를 참고한다.
